# 入力検証とセキュリティの強化（#70）

対応：Issue #70
ID はバックログと同じ T-9xx の空間を使う（段階に紐づかない改善のため）。

画面の入力は `maxLength` 属性と `useState` だけで、**サーバー側の検証に抜けがあった**（回答・メモ・読み上げ文の上限なし、音声ファイルのサイズ・種類チェックなし、面接テーマに任意の文字列が入る など）。
画面とサーバーで**同じ zod スキーマ**を使い、画面の検証をすり抜けた値もサーバーで同じように弾く。

## 方針

| 層 | やること |
| --- | --- |
| 共通（`lib/schemas.ts`） | 文字列は見えない文字（制御・ゼロ幅・双方向制御・タグ文字・孤立サロゲートなど）を除き、1 行の欄は改行も除く。上限・必須・選択肢をスキーマで定義 |
| 画面 | react-hook-form + `zodResolver` で上のスキーマを使い、欄の下にエラーを出す |
| API | 本文は `application/json` のみ・128KB まで（`lib/http.ts`）。未知の項目は拒否。AI の出力・文字起こしは生成時に上限へ切り詰める（サロゲートペアの途中では切らない） |
| proxy | `Sec-Fetch-Site`（無ければ Origin と Host の比較）で、別オリジンからの API への書き込みを 403 |
| ヘッダー | `nosniff`・`X-Frame-Options: DENY`・CSP（`frame-ancestors` 等）・`Referrer-Policy`・`Permissions-Policy`（カメラ・マイクは自サイトのみ）・HSTS。`X-Powered-By` を出さない |
| ログ | 例外は名前と原因コードだけ残す（DB エラーのメッセージには入力値が含まれるため） |
