## 決めたこと

- **古い記録は `null`**。`stage` `company` は nullable にし、`describeConditions` は空の欄を飛ばす。
  そのため #22 より前の記録は「IT／エンジニア／新卒／やさしめ」のまま表示される。
- **表示順は「段階 → 企業タイプ → 面接官レベル」**。「何の面接か」を決めてから「当たりの強さ」を選ぶ流れにした。
- 段階・企業タイプにも説明文（`description`）を付けた。選んだ結果どう変わるかが分からないと選べないため（#43 と同じ考え方）。

## 実測（T-301.4）

商社→企画・マーケ・中途・厳しめ・大手で、テーマを固定して 3 段階の初回質問を比べた。

テーマ「職務経歴・実績」

| 段階 | 初回質問 |
| --- | --- |
| 一次 | これまでの営業企画業務で、特に成果が大きかったプロジェクトと具体的な数値を教えてください。 |
| 二次 | これまでの営業企画業務で、具体的に売上を何％向上させたか、またその際の**ご自身の役割と取った施策**を教えてください。 |
| 最終 | 営業企画での実績と、**当社でどのように活かし貢献したいか**教えてください。 |

テーマ「志望動機」

| 段階 | 初回質問 |
| --- | --- |
| 一次 | 貴方がこれまでの営業企画で培った経験を活かし、当社の企画・マーケティング領域で実現したいことを簡潔に教えてください。 |
| 二次 | 大手商社の企画・マーケティング職を志望された理由と、現職の営業企画で培った経験をどのように活かしたいと考えていますか？ |
| 最終 | 当社の企画・マーケティング職を志望する理由と、**入社後に実現したい具体的な目標**を教えてください。 |

- 最終では両テーマで「入社後」に触れた（確認項目を満たす）。
- 二次は「自分の役割」「数字」に寄り、一次は範囲が広い。狙いどおりの差が出ている。
- テーマが「志望動機」のときは 3 段階の差が小さい。テーマ自体が志望度の話なので自然な結果。

## DB の適用

`stage` `company` は新しいカラムなので、**使う前に適用が必要**。

```bash
npm run db:push    # drizzle/0003_sessions_stage_company.sql の内容
```

適用前に模擬面接や講評を保存しようとすると、カラムが無いため保存に失敗する。
手順は [deployment.md](../../deployment.md) 4 章と同じ。
