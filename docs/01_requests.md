# 要求（Request）

## 1. 背景

就職活動・転職活動における面接対策は、「一人で練習しづらい」「話した内容に客観的なフィードバックがもらえない」「表情や話し方まで意識するのが難しい」という課題がある。
模擬面接を人に頼むのはハードルが高く、練習の記録も残りにくい。

## 2. 目的

ブラウザだけで、いつでも一人で面接練習ができ、AI から即座にフィードバックを受けられる「AI練習コーチ」を提供する。
回答内容だけでなく **表情（笑顔）** も同時に計測し、練習の記録を蓄積して成長を可視化する。

さらに、質問を自分で選ぶ「講評モード」に加えて、面接官役の AI が出題し・回答に応じて深掘りしてくる「模擬面接モード」を提供し、本番に近い緊張感で練習できるようにする。

## 3. 想定ユーザー

| ユーザー | 状況 | 求めていること |
| --- | --- | --- |
| 就活生 | 面接本番が近いが練習相手がいない | 定番質問に対する回答を何度も練習して改善したい |
| 転職希望者 | 仕事の合間に短時間で練習したい | 回答を声に出して話し、すぐに講評が欲しい |
| 自己表現が苦手な人 | 表情が硬いと指摘されたことがある | 話している間の表情を客観的に知りたい |

| 職種（志望先） | エンジニア／営業／企画・マーケ／事務／接客・販売／研究・開発／その他 | **志望先** の職種。業界と組み合わせて質問生成の材料にする |
| 区分 | 新卒／中途 | 新卒は「学生時代」寄り、中途は「実績・転職理由」寄りの質問になることを期待 |
| 現職 | 自由入力（1 行、任意） | **中途を選んだときのみ表示**。例：「総合商社 営業企画 10 年」。志望先との差分（なぜ転職？ 経験はどう活きる？）を問う材料にする |
| 学部・専攻 | 自由入力（1 行、任意） | **新卒を選んだときのみ表示**。例：「経済学部、独学でプログラミング」。志望先との差分（なぜ文系からエンジニア？）を問う材料にする |
| 面接の段階 | 一次／二次／最終 | 一次：人物・基本的な経歴・コミュニケーション／二次：具体的な経験の深掘り・スキル確認／最終：志望度・入社後のビジョン・条件面（役員視点） |
| 企業の規模・タイプ | 大手／中小／ベンチャー／公的機関 | 志望動機の深掘りの角度を変える（「なぜ大手ではなくベンチャー？」など）。企業名は入力させない（AI が実在企業について不正確な発言をするリスクを避ける） |
| 面接官レベル | やさしめ／厳しめ／圧迫 | 既存の「口調」を置き換える。当たりの強さを表す。「圧迫」は圧迫面接の練習で、矛盾や弱点を突いて詰めてくるもの。人格否定や暴言はしない |

### 面接官レベルの表示名と説明文

| キー | 表示名 | 説明文（画面に添える） | 読み上げの声 | 詰め方 |
| --- | --- | --- | --- | --- |
| `kind` | やさしめ | 肯定から入り、答えやすい形で深掘りします | 女性・標準の速さ | 肯定から入り、答えやすく聞く |
| `strict` | 厳しめ | 根拠・数字・具体例を求めます | 男性・やや早口 | 端的に根拠・数字を求める |
| `harsh` | 圧迫 | 矛盾や弱点を突き、詰めてきます（圧迫面接の練習） | 男性・低め・早口 | 相槌なし。弱い回答は一度否定して問い直す。最後の質問で 1 回だけ志望度を疑う |

- レベルを変えると **読み上げの声も変わる**（声・速さ・ピッチの組み合わせ）。レベルの違いを体感できるようにするため（#45）。

- 当初は「優しい／厳しい／意地悪」としていたが、「意地悪」は当たりの強さではなく性格（悪意）を指すため軸がずれており、
  実際に AI が「言っていないことを前提にした質問」をする副作用が出た。圧迫面接という既成の言葉に変更した。

- 現職・学部・専攻は空でも練習を始められる。ただし「入力すると質問が具体的になる」旨を画面に示す。
- 現職・学部・専攻・面接の段階・企業の規模・タイプも REQ-29（前回条件の記憶）の対象に含める。

## 4.1.1 プロフィール設定（REQ-36）

トップ画面とは別に「プロフィール設定」画面を置き、ログインユーザーごとに保存する。一度登録すれば毎回の練習で自動的に使われる。

| 項目 | 入力方法 | 用途 |
| --- | --- | --- |
| ES（エントリーシート） | 自由入力（複数行、任意）。ガクチカ・自己PR・志望動機の骨子など | 「ES にある○○について具体的に」という本番に近い深掘りをさせる |
| 職務経歴書（履歴書形式） | **年・月・内容** の行を追加していく形式（任意）。学歴・職歴を古い順に書く（例：2016 年 4 月「○○大学 経済学部 入学」、2020 年 4 月「○○商事 入社 営業事務」）。免許・資格は別欄に自由入力 | 「○○社での 5 年間の経験は志望先でどう活きますか」など経歴に沿った深掘りをさせる |

- ES と職務経歴書は別々の欄に分ける（同じ欄に混ぜない）。
- 入力欄の近くに **「ここに入力した会社名・学校名などの情報は、面接の質問生成のために AI（外部サービス）へ送信されます」** を明示する（REQ-38）。

- 未登録でも練習はできる。未登録時は「登録すると深掘りが具体的になる」旨をトップに表示する。
- 現職／学部・専攻はトップの面接条件側に置く（面接ごとに変わり得るため）。プロフィールは面接をまたいで変わりにくい情報のみ。

## 4.1.2 入力させない情報（REQ-37）

年齢・性別・出身地・家族構成・思想信条・宗教など、公正な採用選考の観点で聞くべきでない属性は、アプリの入力項目に **含めない**（プロンプトに載る経路を作らない）。
志望企業名も、AI が実在企業について不正確な発言をするリスクがあるため入力させない（規模・タイプで代替）。

## 4.2 模擬面接の進め方（決定事項）

| # | 項目 | 決定 |
| --- | --- | --- |
| 1 | 往復数 | **固定 3 往復**（最初の質問 1 回 ＋ 深掘り 2 回） |
| 2 | テーマ | 1 回の面接で深掘りするテーマは **1 つ**。テーマは面接官（AI）が業界・職種・区分に合わせて **毎回出題** し、直近の練習と同じテーマは避ける。将来「複数テーマ型」へ拡張できる前提で設計する |
| 3 | 途中終了 | 「面接中断」ボタンで途中終了できる。**そこまでの内容で総評を出す** |
| 4 | 回答のやり直し | **できない**（送信した回答は取り消せない。本番の緊張感を再現する） |
| 5 | 考える時間 | ~~質問が出てから回答開始までに考える時間を設ける~~ → **取り下げ**。面接官が話し終えたら自動で録音が始まる（決定事項 31）ので、沈黙がそのまま記録される。待ち時間を機能として設ける必要がなくなった |
| 6 | 短すぎる／空の回答 | 面接官が「もう少し詳しく」と **1 回だけ促す**（往復数は消費しない）。2 回目はそのまま次へ進む ※第 3 段階。第 2 段階では空回答は送信不可にするだけ |
| 7 | 面接官の禁止事項 | 人格否定・暴言をしない。学歴・年齢・家族構成・出身地・思想信条など、公正な採用選考の観点で不適切な質問をしない。返答は必ず質問の形で終える。回答者が言っていないことを前提にした決めつけをしない（#43 で追加） |
| 7.1 | レベルごとの体感差 | 表示名・説明文・**面接官の声（声・速さ・ピッチ）**・詰め方を変えて、レベルを変えたことが分かるようにする（#45）。安全弁（上記の禁止事項）はレベルに関わらず守る |
| 8 | 質問の提示 | テキスト表示に加えて **自動で音声読み上げ** する。声は面接官レベルで切り替える（#45） |
| 9 | 総評の内容 | 内容面（良かった点・改善点）、表情（各往復の話している間の平均笑顔スコア）、話し方（回答の長さ など）の 3 軸 |
| 10 | 保存 | 面接終了（3 往復完了 or 中断）時に **自動保存** |
| 11 | 講評モード | 既存の 1 問 1 答の講評機能は **残す**。トップ画面から「模擬面接」「講評」のどちらかを選ぶ |
| 12 | 講評モードのテーマ | 現在の 4 択に加えて **自由入力** できるようにする（既存画面のトピック欄を、選択と入力の両方に対応する形へ変更）。想定外の質問への対策や、実際の面接で聞かれた質問の復習に使う |
| 13 | 講評モードと面接条件 | トップで選んだ業界・職種・区分・面接官レベルを **講評モードでも使う**。従来の口調（やさしめ／スパルタ／ていねい／関西弁）は面接官レベルに置き換えて廃止 |
| 14 | 履歴の見せ方 | 一覧は「模擬面接」「講評」の **タブ** で切り替える。笑顔グラフもタブごとに表示。模擬面接の詳細は往復ごとに「質問 → 回答」を並べ、最後に総評を表示 |
| 15 | 笑顔スコアの記録 | 模擬面接では **話している間（話し始め〜話し終え）の平均** を往復ごとに記録し、総評の「表情」はその並びをもとにする。送信時点の一瞬の値だと、画面を操作している顔が記録されてしまうため。マイクが使えずテキストで回答した場合は直近の値を使う。講評モードは送信時点の値のまま |
| 16 | 回答時間 | 話す時間の **上限は設けない**（自分で送信）。経過時間は表示し、総評の「話し方」で回答の長さを評価する |
| 17 | 総評の読み上げ | 自動再生はせず、既存の読み上げ UI（再生／停止／音量／速度）で **手動再生** |
| 18 | 前回条件の記憶 | **ログイン必須** とし、前回選んだ面接条件をユーザーごとに保存してトップの初期値にする |
| 19 | 定番テーマ | 区分（新卒／中途）に応じてプルダウンの定番テーマを切り替える。新卒に「転職理由」は出さない。自由入力（REQ-25）と併用 |
| 20 | 履歴からの再挑戦 | 履歴詳細に「このテーマでもう一度（講評モード）」「同じ条件で模擬面接」ボタンを置く。条件・テーマは履歴から引き継ぐ |
| 21 | 過去回答との比較 | 講評モードで同じテーマ（同一ユーザー）の直近の回答がある場合、講評に「前回との比較」を含める。初回は比較なし |
| 22 | NG 表現の指摘 | 講評・総評の「内容面」に、ネガティブ表現・他責的な言い回し・根拠や数字のない実績の指摘と言い換え例を含める。面接官レベルに関わらず必ず指摘する（実装済み・#28） |
| 23 | 現状の入力 | 業界・職種は **志望先** と定義する。区分に応じて「現職」（中途）または「学部・専攻」（新卒）の自由入力欄を表示し、任意で入力させる。質問・深掘り・講評のプロンプトに渡す |
| 24 | 面接の段階・企業タイプ | トップのプルダウンに「面接の段階（一次／二次／最終）」「企業の規模・タイプ（大手／中小／ベンチャー／公的機関）」を追加し、出題傾向と志望動機の深掘りに反映する。前回値を記憶する ※第 3 段階 |
| 25 | プロフィール設定 | 「プロフィール設定」画面で **ES（自由入力）** と **職務経歴書（履歴書形式：年・月・内容の行 ＋ 免許・資格）** を別々に登録し、ユーザーごとに保存。模擬面接・講評の両方でプロンプトに渡す。任意。入力欄の近くに AI 送信の注意書きを置く ※第 2 段階 |
| 26 | 入力させない情報 | 年齢・性別・出身地・家族構成などの属性、および志望企業名は入力項目に含めない |
| 27 | ログイン方式 | **Clerk** を使い、**Google ログインのみ** を提供する。メール＋パスワードの登録・再設定画面は作らない |
| 28 | 模擬面接の回答手段 | **音声のみ**（録音 → 文字起こし）。テキストを書き直しながら考えられないようにし、本番を再現する。マイクが使えない環境向けにテキスト入力のフォールバックのみ残す。講評モードは従来通り音声・テキストの両方可 |
| 29 | 笑顔スコアの記録期間 | ~~質問表示〜送信の期間~~ → **話し始め〜話し終え** の期間に変更（決定事項 15）。質問を聞いている間や、文字起こしを確認している間は含めない |
| 30 | 既存データ | 現在 DB にある `userId = "demo"` のセッションは **破棄** する。ログイン導入時にデータ移行は行わない |
| 31 | 録音の開始 | 面接官の読み上げが終わったら **自動で録音を開始** する。読み上げが失敗したときは質問表示から 1.5 秒後に開始。ユーザーが押すのは「話し終わり」だけ。マイクの許可は「面接を始める」の 1 回で取り、3 往復で使い回す |
| 32 | 回答までの時間 | 文字起こし（Whisper の `verbose_json`）の最初の発話位置を「面接官が話し終えてから声を出すまでの秒数」として記録し、総評の「話し方」で触れる。目安は 3 秒以内なら自然、5 秒を超えたら長い、0〜1 秒の即答は用意した答えに見えることがある。**沈黙を一律に悪いとはしない** |

## 4.3 画面の流れ（イメージ）

```
ログイン
 ↓
トップ画面（/）
 ├ 面接条件を選ぶ（志望業界・志望職種・区分・面接の段階・企業タイプ・面接官レベル ※前回の値が初期値）
 │   ├ 区分に応じて 現職（中途）／学部・専攻（新卒）を任意入力
 │   ├ [模擬面接を始める] → 模擬面接画面
 │   └ [講評モードで練習] → 講評画面（既存の練習画面。テーマは定番 or 自由入力）
 ├ [プロフィール設定]     → ES／職務経歴書（履歴書形式）を登録（任意・ユーザーごと・AI 送信の注意書き）
 └ [履歴を見る]           → 履歴一覧（タブ：模擬面接／講評）→ 履歴詳細
                                                          ├ [このテーマでもう一度] → 講評画面
                                                          └ [同じ条件で模擬面接] → 模擬面接画面

模擬面接画面
  質問（自動読み上げ）→ 考える時間 → 回答（録音のみ ※マイク不可時はテキスト）→ 送信
  → 深掘り質問 → 回答 → 深掘り質問 → 回答
  → 総評（内容・表情・話し方）→ 自動保存
  ※ いつでも [面接中断] → そこまでの総評 → 自動保存
```

## 5. 制約・前提

- Web ブラウザ（PC 想定）で動作すること。カメラ・マイクの使用許可が必要。
- AI・音声認識は外部 API（Groq）を利用する。API キーはサーバー側で管理し、ブラウザには露出させない。
- 学習用課題プロジェクトであり、段階的（Day 単位）に機能を追加する。
- **ログイン必須**。未ログインでは練習・履歴のどちらも利用できない（模擬面接の実装より先に認証を入れる）。

## 5.1 段階分け

**提出期限：2026 年 9 月 27 日**（残り 7 日）。7 日で確実に動くものを優先し、実装コストが高いもの（新しい画面・テーブル・状態管理）は後ろに回す。プロンプトの指示だけで実現できるものは残す。

| 段階 | 目安 | 目的 | 含む要求 |
| --- | --- | --- | --- |
| 第 1 段階（必須） | 3 日 | ログインと画面構成を整え、既存の講評モードを新しい条件体系に載せ替える | REQ-12（Clerk / Google ログイン、履歴のユーザー分離、demo データ破棄）、REQ-13・33（トップ画面：業界・職種・区分・面接官レベル ＋ 現職／学部）、REQ-16・26（口調 → 面接官レベル、条件をプロンプトに反映）、REQ-01・25（区分別定番テーマ・自由入力）、REQ-18（トップ → 履歴）、REQ-37（入力させない情報） |
| 第 2 段階（必須） | 3 日 | 模擬面接モードと、その記録・振り返り | REQ-14・15・17・22（固定 3 往復の出題・深掘り・面接中断・総評・自動保存）、REQ-20（質問の自動読み上げ）、REQ-21（総評 3 軸。表情は往復ごとの送信時スコア）、REQ-23（禁止事項）、REQ-19・27（履歴タブ、模擬面接詳細の往復表示、条件表示）、REQ-36・38（プロフィール設定：ES と職務経歴書を別欄で登録し、深掘りに使う。AI 送信の注意書き） |
| 第 3 段階（余裕があれば） | - | 磨き込み。着手する場合は上から順 | REQ-34・35（面接の段階・企業タイプ：プルダウン 2 つなので最初に）、決定事項 5・6（考える時間、短い回答への促し）、REQ-29（前回条件の記憶）、REQ-30（再挑戦）、REQ-31（前回回答との比較）、REQ-32（NG 表現指摘） |

- 第 1 段階完了時点で、既存機能（講評・履歴）がログイン付きで動く状態にする。
- 第 2 段階完了をもって提出物とする。第 3 段階は時間に余裕があれば着手する。
- 時間が押した場合の削り方：
  - 第 1 段階：講評モード改修を「口調 → 面接官レベル」のみにし、自由入力・区分別定番を第 3 段階へ
  - 第 2 段階：履歴のタブ・往復表示を「一覧に『模擬面接』ラベル＋詳細は総評のみ」に簡略化（往復は JSON カラム 1 本で保存）
  - 第 2 段階：職務経歴書の行形式をやめ、ES・職務経歴書・資格を 3 つの複数行テキスト欄に簡略化（注意書きは残す）
- 既存の `demo` データは第 1 段階のログイン導入時に破棄する（決定事項 30）。

## 6. 将来の候補（今回は見送り）

| 候補 | 背景 | 見送る理由 |
| --- | --- | --- |
| 笑顔スコアの時系列記録 | 総評で「冒頭は硬かったが後半で改善」のような 1 回答の中の推移を示したい | 往復ごとの平均までは実装済み。1 回答の中の推移はまだ |

| 1 回の所要時間の目安表示 | 美香：隙間時間 10 分で練習したい | 効果は小さい。UI が固まってから検討 |
