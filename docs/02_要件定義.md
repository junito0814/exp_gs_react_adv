# 要件定義（Requirements Definition）

[01_要求.md](./01_要求.md) を実現するために、システムが満たすべき要件を定義する。
段階（第 1／第 2／第 3）は要求の 5.1 に従う。**提出期限 2026-09-27**。

状態の凡例：`済` 既存実装で満たしている／`変更` 既存実装を改修する／`新規` 新しく作る／`3` 第 3 段階（余裕があれば）

## 1. システム概要

```
[ブラウザ]                                  [Next.js サーバー]                    [外部サービス]
 /sign-in ─────────────────────────────── Clerk ──────────────────────────────▶ Google (OAuth)
 /          トップ（条件選択）
 /practice  講評モード ── POST /api/coach ──────▶ Groq LLM
 /interview 模擬面接   ── POST /api/interview ──▶ Groq LLM     (質問・深掘り・総評)
                       ── POST /api/transcribe ─▶ Groq Whisper
                       ── POST /api/tts ────────▶ Edge TTS
 /profile   プロフィール ─ GET/PUT /api/profile ─▶ Neon (PostgreSQL)  ※Drizzle
 /history   履歴一覧    ─ GET/POST/DELETE /api/sessions[/:id] ─▶ Neon
 /history/[id] 履歴詳細
```

- フロントエンド: Next.js 16 (App Router) / React 19 / Tailwind CSS 4
- 認証: Clerk（Google ログインのみ）
- 表情解析: `@vladmandic/face-api`（ブラウザ内推論、モデルは `public/models`）
- AI: Groq API（LLM: `openai/gpt-oss-120b`、音声認識: `whisper-large-v3-turbo`）
- 読み上げ: `@andresaya/edge-tts`（`ja-JP-NanamiNeural`）
- DB: Neon (PostgreSQL) + Drizzle ORM

```
/sign-in ──▶ /
             ├─ 条件を選ぶ ─┬─ [講評モードで練習] ──▶ /practice?industry=..&job=..&career=..&level=..&background=..

             ├─ [プロフィール設定] ──▶ /profile
             └─ [履歴を見る] ────────▶ /history?mode=interview|practice ──▶ /history/[id]
```

- 面接条件は **URL クエリ** で `/practice` `/interview` に渡す（リロードしても残る。第 3 段階の「再挑戦」でもリンクで再現できる）。
- 未ログインで保護ページにアクセスした場合は `/sign-in` へリダイレクトする。

## 3. 面接条件（共通の入力仕様）

| キー | 項目 | 型・選択肢 | 必須 | 初期値 | 段階 |
| --- | --- | --- | --- | --- | --- |
| `industry` | 志望業界 | IT／メーカー／金融／商社／小売・サービス／医療・福祉／公務員／その他 | 必須（初期値あり） | IT | 1 |
| `job` | 志望職種 | エンジニア／営業／企画・マーケ／事務／接客・販売／研究・開発／その他 | 必須（初期値あり） | エンジニア | 1 |
| `career` | 区分 | `new`（新卒）／`mid`（中途） | 必須（初期値あり） | 新卒 | 1 |
| `background` | 現職（中途）／学部・専攻（新卒） | 自由入力 1 行、最大 100 文字 | 任意 | 空 | 1 |
| `level` | 面接官レベル | `kind`（やさしめ）／`strict`（厳しめ）／`harsh`（圧迫） | 必須（初期値あり） | やさしめ | 1 |
| `stage` | 面接の段階 | `first`／`second`／`final` | 任意 | 一次 | 3 |
| `company` | 企業の規模・タイプ | `large`／`sme`／`startup`／`public` | 任意 | 大手 | 3 |

- `background` のラベルは `career` に連動して切り替える（新卒：「学部・専攻」、中途：「現職（業界・職種・年数）」）。空でも開始できる。欄の下に「入力すると質問が具体的になります」と表示する。
- 「その他」を選んだ場合の自由入力は第 1 段階では **行わない**（「その他」という値のままプロンプトに渡す）。
- 年齢・性別・出身地・家族構成・志望企業名の入力欄は **設けない**（REQ-37）。
- 選択肢の表示名とキーの対応は 1 か所（例：`lib/options.ts`）で定義し、画面・API・プロンプトで共有する。

## 5. AI プロンプト要件

### 5.1 共通（講評・模擬面接）

- 面接条件（業界・職種・区分・現職／学部・面接官レベル）とプロフィール（登録時のみ）を system プロンプトに含める。
- 面接官レベル（表示名は要求 4.1 参照）ごとの振る舞い：

| レベル | 表示名 | 振る舞い |
| --- | --- | --- |
| `kind` | やさしめ | 肯定から入る。深掘りは「もう少し教えてください」型。言い換え例を多めに |
| `strict` | 厳しめ | 端的。根拠・数字・具体例を求める。曖昧な回答には「具体的には？」と返す |
| `harsh` | 圧迫 | 圧迫面接の面接官として、回答の矛盾や弱点を突いて詰める。「本当にそうですか？」「他の会社でもよいのでは？」のような深掘り。ただし下記の禁止事項を厳守し、回答者が言っていないことを前提にしない |

- **禁止事項**（全レベル共通、system プロンプトに明記）：人格否定・暴言をしない。年齢・性別・出身地・家族構成・思想信条・宗教など公正な採用選考の観点で不適切な質問をしない。
- 区分による出題傾向：新卒は学生時代の経験・志望動機・人柄、中途は実績・転職理由・志望先での再現性。新卒に「転職理由」を出さない。
- `background` があれば「現状 → 志望先」の差分（なぜ転職？ なぜ文系からエンジニア？）を必ず 1 度は問う。
- プロフィールがあれば「ES にある○○について」「○○社での経験は」のように具体的に参照する。ES・職務経歴書・免許資格は見出し付きで system プロンプトに含める。

### 5.2 講評（`/api/coach`）

既存フォーマットを維持し、口調のみ `level` に置き換える。

### 5.3 模擬面接・質問生成（`/api/interview`）

- 役割：「あなたは面接官です。1 回の返答で質問を 1 つだけ出してください。講評・励まし・解説はしないでください。返答は必ず質問文で終えてください」
- 出力：質問文のみ（前置き・番号なし、100 文字以内）。JSON `{ "question": "..." }` で返させ、パース失敗時はテキスト全体を質問として扱う。
- `turns` が空：条件に合うテーマを 1 つ選んで最初の質問を出す。
- `turns` あり：`messages` に `[system, assistant: Q1, user: A1, ...]` の形で履歴を渡し、直前の回答の内容を引用しつつ深掘りする。テーマは変えない。

### 5.4 総評（`/api/interview/summary`）

- 入力に各往復の質問・回答・笑顔スコア・回答秒数を含める。
- 出力フォーマット：

```
■ 内容面
・良かった点（1〜2 点）
・改善点（1〜2 点）→ 言い換え例：「…」

■ 表情
・各往復の笑顔スコア（例：1 問目 35% → 2 問目 62% → 3 問目 70%）をもとに一言

■ 話し方
・各回答の長さ（秒数・文字数）をもとに、長すぎ／短すぎ／ちょうどよい と根拠
```

- 全体 300〜450 文字、`level` に応じた口調。回答の目安：1 回答 45〜90 秒・200〜400 文字。

## 7. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | セキュリティ | `GROQ_API_KEY` `DATABASE_URL` `CLERK_SECRET_KEY` はサーバー側のみ。`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` 以外をブラウザに出さない |
| NFR-02 | セキュリティ | `.env.local` は Git 管理外 |
| NFR-03 | セキュリティ | すべての DB 操作は Clerk の `userId` で絞り込む。body の `userId` は使わない |
| NFR-04 | プライバシー | カメラ映像はブラウザ内で解析しサーバーへ送らない。音声は文字起こし目的でのみ Groq に送り、保存しない。プロフィール（ES・職務経歴書）は質問生成のために Groq へ送信されるため、その旨を入力画面に明示する（FR-F05） |
| NFR-05 | 性能 | 笑顔計測は 0.5 秒間隔で UI をブロックしない。face-api は動的 import |
| NFR-06 | 可用性 | 外部 API・ネットワーク失敗時はエラー表示と再試行に留め、アプリがクラッシュしない。模擬面接の途中で失敗しても、蓄積した往復は失わない |
| NFR-07 | UI | ダークモード対応（既存の配色を踏襲）。PC 幅を前提とし、スマートフォン最適化は行わない |
| NFR-08 | 保守性 | TypeScript / ESLint に準拠。選択肢・プロンプトは `lib/` に切り出し、画面と API で共有 |
| NFR-09 | 環境 | Node.js 20 以上、Next.js 16 の規約（`params` `searchParams` は `await`、`proxy.ts` による保護）に従う。実装前に `node_modules/next/dist/docs/` を確認する |
